### The CHANGELOG claim, corrected — with the evidence

`CHANGELOG/README.md` said a PR "opens with a placeholder file named for the entry's planned date; the org-wide pr-validator finalizes it to the merge-time CalVer before landing. Every PR must include a CHANGELOG entry (validator rule B19)." That is not what the org does, and `AGENTS.md` said the opposite in the same commit. The ground truth:

- `opencharly/.github/.github/workflows/tag-on-merge.yml` — "CHANGELOG content = the PR body itself (title + body) … the PR body IS the changelog", written at merge time to `CHANGELOG/<calver>.md`, "create if missing".
- `opencharly/.github/.github/workflows/pr-validator.yml` — "*No CHANGELOG rename — the merge workflow creates CHANGELOG from PR body.*"
- `marketplace/internals/agents/pr-validator.md` rule 18 — "**PR body IS the changelog.** No CHANGELOG file is staged in the PR diff … A CHANGELOG file in the diff is neither required nor expected."
- Sibling repos carry `CHANGELOG/<CalVer>.md` names that match their tags 1:1 (`layer-sherpa-onnx`: `2026.272.0445.md` ↔ `v2026.272.0445`).

An author-time placeholder would carry a name that can never match the merge-time stamp, so it would survive as a stray, untagged entry beside the real one. Both files now describe the real contract, so the two statements agree — the fix that finding asked for, on the side that matches reality (R4a: establish which side holds the intent, then fix to it).

### One platform constraint found while fixing this, and recorded

The first attempt at single-sourcing the model name (using `${KOKORO_MODEL}` in the check steps) **silently disarmed six checks**: a `check:` step's fields resolve only the auto-exports (`${HOME}`, `${USER}`, `${ARCH}`), and a candy `var:` makes the step report

```
SKIP  check the Kokoro ONNX model is present  [plan:candy:kokoro-tts:1]  unresolved variables: KOKORO_MODEL
```

— a SKIP, not a failure, so the bed still printed PASS (9 skips, 23 steps). That is an R1 anomaly, and it is fixed at the root here: the literal model name in the check steps is deliberate, both `charly.yml` and `AGENTS.md` say why, and the `run:` steps (download + verify) keep the `${KOKORO_MODEL}` interpolation they legitimately resolve. The final run asserts **zero** unresolved-variable skips.
